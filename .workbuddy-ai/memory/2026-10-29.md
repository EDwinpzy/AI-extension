## 修复：添加模型对话框「读取模型列表」一直卡住
- 现象：云端模型选 Command Code + 填 Key 后，模型下拉为空，提示停在「正在读取模型列表…」永不返回。
- 根因：`darkling/glue.js` 顶层调用 `chrome.commands.onCommand`，而 manifest 没有 `commands` 段 → `chrome.commands` 为 undefined → importScripts 抛 TypeError → **整个 service worker 安装失败**，于是 `chrome.runtime.sendMessage` 既不 resolve 也不 reject，所有消息（含 `__ping`、get-settings、list-models）全部挂起。与 `handleListModels` 无关。
- 修复：manifest.json 增加 `commands.toggle-darkling`（Alt+Shift+D）；glue.js 里对该 API 加存在性判断，防止同类问题再次拖垮 worker。
- 验证方式（可复用）：Edge 156 已禁用 `--load-extension`，改用 CDP `Extensions.loadUnpacked`（需 `--enable-unsafe-extension-debugging` + `--remote-debugging-port`），再在扩展页上下文里 `chrome.runtime.sendMessage` 打桩探测；修复后 list-models 返回 94 个模型。
- 调试脚手架待清理：`msgtest.html` / `msgtest.js`、`background-loader.js` 里的 `__ping` 监听、`engine.js` 的 `console.log('[engine] onMessage')`。

## 修复：大部分功能没有后台支撑（v1.0.5）
- 现象：翻译、字幕、摘要、暗色、书签全部无反应，设置页本身正常。
- 根因三处：① manifest 缺 `scripting` 与 `bookmarks` 权限；② 完全没有 `content_scripts`，`translate/content.js` / `subtitle.js` 从不注入；③ 根 `background-loader.js` 没导入 `bookmarks/worker.js`，而面板早已通过 port 连它。
- 修复：补两项权限；声明 content_scripts（`<all_urls>`，document_idle）；loader 按 settings → engine → bookmarks → darkling 顺序导入。
- 测试台（临时目录 `%TEMP%/ai-ext-debug`）：`server.mjs` 本地 mock 模型 + 测试页，`e2e.mjs` 用 CDP 驱动 Edge 跑 17 项断言，全部读取页面 DOM/存储而非函数返回值。修复后 17/17，连跑两轮稳定。
- 踩坑记录：断言写成 `includes('translated')` 会匹配 `not-translated`；透明背景亮度要按 255 算；暗色开关视觉状态可能与引擎状态不同步，需以 `isEnabled` 为准。
- 已知噪声：暗色开关切换时 worker 有 3 条 `Could not establish connection` 未捕获拒绝（向无内容脚本的标签页发消息），不影响功能。

## 修复：总结全文「没反应」（v1.0.7）
- 两条静默返回：① `pageScriptReady` 失败时 `summarizeIntoPanel` 直接 return，界面零反馈（浏览器内置页/PDF/商店页必然如此）；② `chrome.sidePanel` 在本插件里不存在（manifest 无 `side_panel`，仓库也无面板页面），每次先闪一句「正在交给侧边栏…」再回落。
- 修复：注入失败改为发通知说明原因；`sidePanelAvailable()` 判断不存在就直接走页面内总结。
- 正常页面实测：0s「正在总结…」→ 2s 出内容；不可注入的 tab → 生成 `codex-summary-unavailable` 通知。
- 排障教训：测试脚本若没关掉同 URL 的旧标签页，`chrome.tabs.query(...)[0]` 可能选中旧页，导致「面板不出现」的假象——实际渲染在另一个 tab。

## 复现并修掉「翻译/总结在旧标签页上失效」（v1.0.8）
- 决定性实验：全新配置下**先开页面、后加载扩展** → 页面里 `data-codex-translate` 始终是 `null`。声明式 content_scripts 只在导航时注入，扩展重载不会补进已打开的标签页。
- 这就是用户「翻译失效、总结没反应」的主因：重载扩展后直接在旧标签页上右键。
- v1.0.8 起 `sendToPage()` 先 ping、失败则 `chrome.scripting.executeScript` 现场注入 content.js + summary.js，再发消息；实测旧标签页从 `null` 变 `ready` 且译文正常落位。
- 功能实测（mock 模型）：字幕——原字幕 `visibility:hidden`、字幕条显示「译·…」、模型被调用；整页翻译——段落带 `data-codex-translated="bilingual"`，原文后接译文，H1/P/按钮都翻，还原后译文消失。
- mock 注意：字幕请求是纯文本（含 `Translate now:` 标记），回显脚手架会污染字幕条。
